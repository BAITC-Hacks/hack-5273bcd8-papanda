## MUST HAVE

- Уточнение пользователя 23.09: центральная AI-функция — движок построения мира задачи и проверки его на противоречивость. Применяется к исходному описанию и повторно к ответам, изменениям и другим содержательным уточнениям; вопросы выводятся из актуального мира, а не только из списка незаполненных полей.
- Мир содержит только сообщённые пользователем утверждения с указанием источника (черновик, конкретный ответ или правка). Интерпретации модели, неизвестные сведения и кандидаты в противоречия отделены от пользовательских фактов. У модели нет права добавлять предположения в карточку как факты.
- Проверка различает нехватку сведений, неоднозначность и возможное противоречие. Противоречие не выдумывается ради завершения процесса; отсутствие найденных противоречий не доказывает истинность описания.
- Для кандидата в противоречие показываются исходные утверждения и вопрос бизнесу. Модель не разрешает конфликт выдуманным фактом и не выбирает трактовку молча. После ответа мир и вопросы пересматриваются; изменение подтверждённых сведений требует повторного подтверждения.
- Запреты раздела 5 ТЗ: AI не добавляет факты, не назначает команды и не ограничивает общий каталог; персональные и чувствительные признаки участников не используются. Текст доступен для редактирования и подтверждается человеком до публикации. Контакт бизнеса, требуемый карточкой, не используется как признак AI-оценки или рекомендаций.

- Структурированный AI-ответ с проверкой формата; отсутствие пользовательских сведений сохраняется явно, факты не выдумываются.
- Редактируемая карточка: название, контекст, потребность, пользователи, данные, ограничения, ожидаемый результат, критерии успеха, контакт, формат взаимодействия.

- Минимальный подтверждаемый этап для выбранной команды и начисление баллов за него, без повторного начисления. Размер баллов — продуктовая настройка, не официальный критерий ТЗ.

## Минимальная архитектура — предложение

Python + FastAPI + SQLite, интерфейс React/Vite согласно последующему промпту пользователя.
Один сервер; демонстрационное переключение бизнеса/команд без полноценной регистрации.
Рейтинг рассчитывает код по явным правилам. AI-движок строит мир задачи из пользовательских
утверждений, проверяет согласованность и выводит уточняющие вопросы; после содержательных
ответов и правок повторяет этот цикл. Конкретную реализацию диалектических стадий нужно
согласовать с методологией, не подменяя её обычным одноразовым анализом полноты.
Системная логика хранит версии и источники, проверяет структуру ответа и ссылки на исходный
текст. Точные цитаты проверяются программно; совпадение цитаты само по себе не доказывает
правильность интерпретации. Пользователь видит основания вопросов и подтверждает факты.
Для карточки предпочтителен перенос исходных пользовательских формулировок; новые
содержательные утверждения модели отклоняются или превращаются в вопросы, а не в факты.
Один настраиваемый AI-провайдер, ключ только на сервере; ограниченный таймаут,
проверка структурированного ответа и честно обозначенный локальный демонстрационный режим.
Точную модель выбрать при проверке доступного API.
Исходные README.md и mini_agent.py организатора сохранить. Инструкцию MVP добавить отдельно
и обеспечить её обнаружение из README без удаления исходного содержания.
Код DialecticAI не переносится; при использовании методологии раскрыть её происхождение.

## RISKS

- Доступ к API ещё не проверен реальным запросом; наличие промокредита не подтверждает его.
- Заполнение поля само по себе не доказывает качество содержания; требуется понятная проверка и ручное подтверждение.
- Пункт о баллах команд присутствует в сквозном сценарии без формулы: минимальная механика будет явно описана как решение команды.
- Организаторские данные пока не предоставлены; синтетические данные нужно обозначить.
- Свежесть origin относительно сервера пока не проверена; локальное дерево до записи документов было чистым.
- Нельзя гарантировать отсутствие галлюцинаций одной инструкцией; нужны проверка ответа и подтверждение человеком.
