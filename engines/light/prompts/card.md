Оцени по фактическим ответам каждое противоречие: resolved, not_resolved или new_gap. Пустой ответ/«не знаю» не разрешает пробел. Объяснения по-русски. Не изобретай новые противоречия: используй существующие ID, new_gap обозначает новое неизвестное в этом же поле.
Для conflict проверяй обе несовместимые стороны вместе с ответами: resolved допустим только если пользователь явно устранил несовместимость, уточнил применимость сторон или отменил одно из утверждений. Наличие нового материала само по себе не отменяет запрет его использования. Например, после «использовать только внутреннее расписание» и «доступ к внутреннему расписанию запрещён» ответ «доступен CSV с расписанием» ещё не подтверждает, что CSV разрешено использовать для прототипа и что он удовлетворяет требованию к источнику. Сохрани not_resolved; если ответ выявил конкретное новое неизвестное в том же поле, используй new_gap и объясни, какое уточнение необходимо. Не выдавай наличие любого непустого ответа за разрешение конфликта.
Собери карточку только по черновику и ответам. Каждый непустой value ссылается на источник draft или A1,A2 и точную quote. value обязан дословно равняться quote либо нескольким quote, соединённым пробелом. Используй целый источник или полные предложения, сохраняй отрицания и пунктуацию. Не пересказывай. Не добавляй числа, сроки, имена, названия или свойства, которых нет в источниках. answer_fields задаёт назначение ответа; не помещай ответ о результате в users. Не размножай общий черновик по всем полям. Неизвестное/null нормально; за неполноту не выдумывай факты. contact всегда null. interaction_format — консультации и обратная связь бизнеса, не интерфейс. users — только сообщённые роли пользователей. Верни assessment и card по схеме. Это неподтверждённый черновик, не публикация.
Явное уточнение пользователя заменяет только тот прежний факт, который оно действительно уточняет. Если отсутствие данных заменено сведениями о доступных данных, не переноси устаревшее «данных нет» в constraints, context или другое поле. Перед возвратом сопоставь значения всех полей: они не должны вновь утверждать отменённые сведения. Если единственная полная цитата для нужного факта одновременно содержит устаревшее утверждение (например, «Данных пока нет, срок — месяц.» после уточнения о доступном CSV), оставь соответствующее поле null, без sources. Нельзя обрезать эту цитату до части предложения или сохранять её целиком ради срока. В explanation укажи необходимость отдельного чистого уточнения срока. Если для этого поля уже есть соответствующее противоречие, обозначь его new_gap для уточняющего вопроса; не создавай новый ID и не меняй назначение существующего противоречия. Не отменённый явно запрет сохраняется как ограничение, а связанный конфликт остаётся неразрешённым.
При correction исправляй только перечисленные сломанные поля; если факт нельзя обосновать — null.
