# Демонстрация AI Sana — план до пяти минут

Сценарий соответствует текущему интерфейсу с одним простым движком. Полный продуктовый путь пройден в браузере; отдельная репетиция до пяти минут и её длительность требуют подтверждения в [VERIFICATION.md](docs/VERIFICATION.md). Расписание ниже — план, не измеренный результат.

## Подготовка

Следовать [README](README.md): установить зависимости, явно собрать frontend, настроить разные модели исполнителя и судьи, запустить приложение. Использовать новую демонстрационную базу, не удаляя прежнюю. Открыть адрес сервера и выбрать «Бизнес». Все сведения примера синтетические.

Начальный режим интерфейс получает из health. Для живого показа настройте AI_MODE=engine; AI_MODE=stub запускает явно обозначенную заглушку. До показа проверить провайдер; не выдавать заглушку или запись за текущий AI-запрос.

## Сценарий

| Время | Действие | Что показать |
|---|---|---|
| 0:00–0:25 | «Новая задача»: тема «Образование», слабый черновик ниже; «Создать черновик» | Краткий ввод; AI-проверка начинается автоматически |
| 0:25–1:30 | Дождаться вопросов | Вопросы с пояснениями; кратко открыть «Как это работает?» |
| 1:30–2:30 | Ответить по смыслу вопросов, «Отправить уточнения»; при втором круге ответить на него | Пояснение вопроса и ответ бизнеса; «Источники» в карточке |
| 2:30–3:15 | Дополнить поля, отметить «Подтверждаю сведения», «Сохранить и пересчитать» | Нулевые баллы неподтверждённых полей, рост после подтверждения, расшифровка |
| 3:15–3:40 | «Опубликовать задачу», «Открытый каталог» | Рейтинг, золотое выделение приоритетной задачи, фильтры «Тема»/«Готовность», доступность слабых опубликованных задач |
| 3:40–4:15 | «Студент», Data Qanat, открыть задачу, заполнить отклик, «Отправить предложение» | Самостоятельный выбор задачи студентами |
| 4:15–4:45 | «Бизнес», открыть отклик, «Выбрать команду» | Ручное решение; также доступно «Отклонить» |
| 4:45–5:00 | «Подтвердить выполненный этап · +10», «Команды и прогресс» | Баллы за подтверждённый результат; назвать этап синтетическим |

Если API не уложится в отведённое время, план пяти минут не считается выполненным: нужно зафиксировать фактическое время и подготовить честный формат показа. Обязательные переходы нельзя заменять слайдами.

## Синтетический пример

Черновик: «Учебному центру нужен помощник для вопросов о курсах. Данных пока нет, срок — месяц». Это пример неполноты, не доказательство конфликта.

Ответы даются по смыслу фактически заданного вопроса. Остальное можно вручную дополнить после завершения анализа.

| Поле | Ответ или ручное дополнение |
|---|---|
| Название | Помощник учебного центра |
| Контекст | Администраторы учебного центра вручную отвечают на повторяющиеся вопросы о расписании |
| Потребность | Сократить повторяющиеся ответы администратора на вопросы о расписании курсов |
| Пользователи | Будущие слушатели курсов и администраторы учебного центра |
| Данные | Уточняем исходное описание: доступен CSV с расписанием и 30 обезличенных вопросов |
| Ограничения | Срок прототипа — 4 недели, Python, только публичные учебные данные |
| Результат | Веб-прототип помощника по расписанию с передачей неизвестных вопросов администратору |
| Успех | Не менее 80% из 30 тестовых вопросов получают ответ со ссылкой на расписание |
| Контакт, вручную | demo@example.test |
| Взаимодействие | Бизнес проводит консультацию раз в неделю и отвечает на вопросы в течение двух дней |

Отклик: идея — «Соберём помощника по расписанию на предоставленном CSV»; план — «Проверим данные, создадим прототип и сравним ответы с критериями бизнеса»; срок — «4 недели»; ссылка — https://example.test/prototype, явно синтетическая.

## Объяснение архитектуры за двадцать секунд

«Мы сначала сопоставляем сведения бизнеса с условиями старта команды. Из пробелов и противоречий возникают вопросы. Ответы проверяются относительно найденных проблем и становятся источниками карточки. Поэтому видно, зачем задан вопрос и откуда появилась формулировка. Рейтинг считает код, публикацию и выбор команды подтверждает человек».

Не утверждать, что каждый этап одобрен судьёй, все противоречия устранены или цитаты доказывают истину. Пробел и противоречие различаются в модели анализа. Ручные изменения автоматически не запускают AI; «Проверить заново» использует черновик и сохранённые допустимые источники. Все существенные ограничения вручную сверяются с карточкой.

## Если API недоступен

Показать реальную ошибку. Нажать «Продолжить без ИИ», показать подпись «Без ИИ · локальная заглушка». Ответить на детерминированные вопросы, проверить и подтвердить карточку, затем продолжить публикацию и отклики. Резервный режим не является успешным живым AI-прогоном. Альтернативно после ошибки можно вручную дополнить карточку.

«Посмотреть промпт и формат AI» открывает промпты, схемы и доступные примеры отказов; также доступен /api/ai/contract. Явный резервный режим доступен после ошибки через «Продолжить без ИИ». Он не анализирует противоречия; не заявляйте обратное.

По §5 ТЗ заглушка допустима при недоступности API, но требует показа промпта, входа, выхода и обработки некорректного ответа. Одного упоминания заглушки недостаточно для подтверждения такого показа.
