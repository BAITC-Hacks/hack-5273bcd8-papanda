# Приложение и архитектура AI Sana

Текущая версия использует один простой движок проверки полноты и противоречий light. Установка — в [README](../README.md), интерфейсы — в [CONTRACT.md](../CONTRACT.md), фактические результаты — в [VERIFICATION.md](VERIFICATION.md). Описание реализации не заменяет новый прогон.

## Запуск и хранение

FastAPI обслуживает API и собранный React/Vite-интерфейс одним сервером. `sana` собирает интерфейс только при отсутствии `web/dist/index.html`. После изменения frontend нужна отдельная `npm --prefix web run build` из корня. Старый dist автоматически не пересобирается.

SQLite создаётся и заполняется синтетическим набором при открытии новой базы. `SANA_DB` задаёт путь; для проверки используйте отдельную базу, не удаляя предыдущую. Карточки, команды и отклики сохраняются; активные AI-прогоны живут в памяти и после перезапуска не возобновляются.

## Проверка противоречий и наглядность

Сначала строится модель ситуации: сообщённые бизнесом сведения и условия, необходимые команде для старта. Пробел означает отсутствие информации; конфликт — несовместимость сведений. Вопросы связаны с конкретными проблемами. Ответы становятся источниками, а проблемы повторно оцениваются.

Позиция команды задана предметной областью, а не выбирается моделью заново. Первый круг содержит 3–5 вопросов; всего не более двух кругов. Второй возможен при новом неизвестном в значимом поле. Движок не обязан устранить всю неполноту и не выполняет произвольную перестройку мира после каждого изменения.

Граф связывает сведения бизнеса, условия старта, проблемы, вопросы и ответы внутри состояния анализа. На экране вместо подробных блоков показаны короткая подпись и диалог «Как это работает?», а у вопросов — пояснения. Цитаты доступны в карточке. Польза — возможность объяснить основание уточнения и происхождение текста. Улучшение сроков проектов экспериментально не измерено.

Создание черновика автоматически запускает выбранный режим; начальное значение берётся из /api/health. Для существующей задачи доступны «Проверить описание» или «Проверить заново». Ручное сохранение не запускает AI. Повторный запуск адаптера получает исходный текст и допустимые сохранённые prior_sources, включая предыдущие ответы и правки. Это сохраняет контекст, но не гарантирует правильной интерпретации всех ограничений.

## Модели, источники и человек

Исполнитель предлагает анализ и вопросы. Включаемый судья плана проверяет уместность вопросов и условия старта. При недоступности этого судьи анализ может продолжиться с записью ошибки. Исправленный план проверяется структурно, без обязательного второго вызова судьи.

Карточка сначала собирается из полных цитат или предложений. Проверяются источник, назначение ответа полю и актуальный содержательный ответ. Неизвестное допускается пустым; контакт модель не создаёт.

Перефразирование проходит программные ограничения и отдельного судью; при отказе или недоступности судьи остаются цитаты. Формулировка не должна менять баллы поля. Адаптер повторно проверяет источники. Человек редактирует и подтверждает результат; AI не публикует и не выбирает команды.

Цитата подтверждает происхождение, а не объективную истину. Судья и эвристики не исключают все смысловые ошибки. Рейтинг измеряет заполненность по правилам, а не сертифицирует качество задачи.

## Действующие настройки

| Настройка | Поведение |
|---|---|
| AI_MODE | Серверный режим: stub, light или engine; engine означает light |
| ENGINE | Для самостоятельного сервиса допустим light |
| SANA_DB | Путь SQLite |
| HOST / PORT | По умолчанию 127.0.0.1:8000 |
| ACTOR_PROVIDER / JUDGE_PROVIDER | openai, nvidia, custom или gigachat |
| ACTOR_MODEL / JUDGE_MODEL | Разные модели; запасные имена AI_ACTOR_MODEL / AI_JUDGE_MODEL |
| OPENAI_API_KEY / OPENAI_BASE_URL | Ключ и endpoint OpenAI |
| NVIDIA_API_KEY / NVIDIA_BASE_URL | Ключ и endpoint NVIDIA NIM |
| CUSTOM_API_KEY / CUSTOM_BASE_URL | Пользовательский совместимый провайдер |
| GIGACHAT_AUTH_KEY / GIGACHAT_CA_BUNDLE | Авторизация и необязательный сертификат |
| LIGHT_JUDGE | Проверка первоначального плана, по умолчанию 1 |
| LIGHT_MAX_ROUNDS | Ограничено диапазоном 1–2 |
| LIGHT_MAX_CALLS | Бюджет light, по умолчанию 10 вызовов |
| LIGHT_DEADLINE_S | Бюджет запросов моделей, по умолчанию 90 секунд |
| ANSWER_TIMEOUT_S | Ожидание ответов, по умолчанию 900 секунд |
| AI_RUN_TIMEOUT | Общий срок продуктового прогона, включая человека |
| AI_TRACE_DIR | События продукта, локальные трассы исключены из Git |

Старые AI_MAX_CALLS / AI_MAX_SECONDS не являются бюджетами light. AI_ACTOR_API_KEY / AI_JUDGE_API_KEY не используются текущим клиентом ролей: ключ и endpoint выбираются по провайдеру.

## Резервный режим и ограничения

Backend содержит детерминированную заглушку. Интерфейс уважает режим из /api/health и показывает, выполняется AI или локальная заглушка. После ошибки AI кнопка «Продолжить без ИИ» запускает stub только по решению пользователя. Заглушка не анализирует противоречия и не выдаётся за успешный живой AI. Runtime-проверка нового UI указывается отдельно в VERIFICATION.md.

«Посмотреть промпт и формат AI» открывает контракт; также доступны `/api/ai/contract` и `/docs`. Возможность показать резервный сценарий и некорректный ответ должна быть проверена по §5 ТЗ.

Роли демонстрационные, без авторизации и проверки владельцев. Контакт исключается из моделей, но обнаружение контактов в свободном тексте не является полной очисткой персональных данных. Используйте синтетические сведения. Ключи находятся на сервере; `.env`, базы и трассы не публикуются. Трассы могут содержать задачи и ответы. Нагрузка, качество реального AI и длительность демо подтверждаются только отдельными проверками.
