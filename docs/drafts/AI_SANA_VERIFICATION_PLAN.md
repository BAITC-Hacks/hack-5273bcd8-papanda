Дата подготовки: 23.09.2026. Основание: TASK.md конкурсного репозитория.
Статус: подготовка; этот документ не подтверждает выполнение тестов.
Проверяется приложение с простым движком после завершения изменений другим агентом.

## Условия начала

Пока идёт запись демо, выполняется только чтение файлов и подготовка отдельных документов.
После завершения изменений — проверка состава файлов и отсутствия секретов, содержательный
коммит и push по указанию пользователя. Фиксируется хеш проверяемой версии.
Полный прогон использует отдельную синтетическую базу и отдельный сервер, чтобы сохранить демо.
Пользователь разрешил содержательные проверки реальных API без чрезмерной экономии токенов.

## Реальный AI: набор ситуаций

1. Короткое описание с пробелами: вопросы относятся к сообщённой задаче.
2. Подробное согласованное описание: движок не выдумывает конфликты ради анализа.
3. Явно несовместимые требования: видна связь найденной проблемы и вопроса.
4. Ответ «не знаю»: пробел не объявляется устранённым без сведений.
5. Явное исправление предыдущего ответа: старое и новое утверждения не смешиваются.
6. Отрицание, числа, сроки, названия и ссылки: смысл и факты сохраняются.
7. Попытка навязать ИИ выдуманные сведения или автоматический выбор команды: продуктовые ограничения сохраняются.

Для каждого запуска фиксируются исходные данные, вопросы, ответы, итог, число вызовов,
доступная статистика токенов и задержки. Стоимость указывается только при наличии
проверенных тарифов/данных; отсутствие статистики не заменяется оценкой без маркировки.
Искусственные ошибки ответа проверяются отдельно и не выдаются за реальные ответы API.

## Нагрузка и устойчивость

Ограниченные серии одновременных запросов к отдельному экземпляру: чтение каталога,
сохранение разных задач, повторные отклики и подтверждения этапа. Проверяется изоляция
разных AI-прогонов, обработка повторного анализа одной задачи, устаревших ответов,
таймаутов и отмены. Нагрузка увеличивается по наблюдаемому поведению с записью
фактического количества запросов, ошибок и задержек. Это проверка MVP, не заявление
о готовности к промышленной нагрузке. Живые параллельные вызовы не направляются
на сервер, на котором записывается демонстрация.
