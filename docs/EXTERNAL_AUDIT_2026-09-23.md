## 2. Кейс, продукт и распределение ответственности

Источник требований — `TASK.md`: бизнес вводит слабое описание; система помогает уточнить его; человек подтверждает карточку; приложение рассчитывает готовность и публикует задачу. Любая команда может откликнуться, бизнес выбирает одну, несколько или ни одной команды. Подтверждённый прогресс выбранной команды приносит баллы.

Оценивание: сквозной сценарий 20, карточка 15, геймификация бизнеса 25, каталог/отклики 15, AI 10, техническое качество 10, демонстрация 5. AI не принимает решений о публикации, рейтинге или назначении исполнителя. Эти функции выполняет обычный код и пользователь.

Существующий код прежнего DialecticAI не переносился согласно принятому ограничению; новая реализация использует методологию. Внешний аудит может проверить Git-историю, но этот документ не является независимой экспертизой происхождения каждой строки.

## 3. Архитектура текущего работающего приложения

```text
React / Vite (web/src/main.jsx)
          ↓ HTTP /api, опрос состояния AI
FastAPI (app/api/__init__.py)
  ├─ scoring.py / catalog.py — правила без LLM
  ├─ store.py — SQLite, карточки, команды, отклики
  └─ ai/service.py — отдельный асинхронный прогон на задачу
       ├─ явная локальная заглушка
       └─ ai/engine.py — actor → judge → вопросы → ответы → карточка
```

`sana` вызывает `app/launcher.py`: при отсутствии `web/dist/index.html` собирает интерфейс, затем запускает один Uvicorn-сервер. FastAPI раздаёт SPA. Неизвестный `/api/...` возвращает 404, не HTML. Для разработки разрешён CORS с localhost/127.0.0.1.

Данные и AI-прогоны имеют разный срок жизни: карточки/команды/отклики сохраняются в SQLite; активные задания, ответы в незавершённом прогоне и состояние исполнения находятся в памяти процесса. Перезапуск не восстанавливает незавершённый AI-прогон. JSONL-трасса фиксирует события, но не является механизмом восстановления.

## 4. Диалектическая концепция и её фактическая реализация

Потребность бизнеса сопоставляется с условиями, при которых студенческая команда может начать работу. Мир включает цитируемые утверждения пользователя. Возможные пробелы, неоднозначности и противоречия имеют ссылки на эти утверждения и остаются интерпретациями, требующими проверки.

Текущий `app/ai/engine.py` выполняет ограниченную последовательность:

1. Actor строит мир и противоположные требования бизнеса/исполнителя.
2. Программный валидатор проверяет ссылки, цитаты и структуру; для противоречия нужны два разных утверждения.
3. Другая модель-judge принимает или отклоняет кандидаты.
4. Actor формирует 3–5 вопросов по принятым кандидатам; вопросы должны затрагивать разные поля.
5. Ответы человека становятся новыми источниками; строится новая версия мира.
6. Формируется карточка из цитат, проверяется происхождение, назначение ответов полям и смысловая верность.
7. Успешный результат остаётся `ai_proposed`, затем требуется подтверждение бизнеса.

Это **фиксированный ограниченный цикл**, а не доказанно полный открытый граф действий прежнего движка. Он не должен называться уже завершённым тяжёлым движком. Отсутствие противоречий допустимо; придумывать их ради демонстрации запрещено.

Ограничители текущего пути: максимум два круга вопросов; предел вызовов задаётся `AI_MAX_CALLS`, но код ограничивает его сверху 12; время внешних вызовов ограничено `AI_MAX_SECONDS`, сверху 240 секунд; ожидание отдельного HTTP-запроса — не более 45 секунд; общий срок прогона, включая человека, задаётся `AI_RUN_TIMEOUT`. Одно корректирующее повторение резервируется по фактической ошибке схемы, источников или судьи. Поля `calls`, `tokens`, `elapsed_seconds`, `stop_reason` доступны в состоянии.

### Новые два движка — в работе

В текущей истории Git зафиксированы общий контракт `engines/common/contracts.py`, протокол `Engine`, выбор `ENGINE=light|heavy`, HTTP-адаптер `engines/service.py` и начальные пакеты light/heavy. Вход включает черновик и веса полей; выход — вопросы, карточку, граф, состояние и метрики. Предусмотрены start/view/submit_answers/cancel/trace. Общие клиенты моделей, канал ответов, трасса и проверка источников уже написаны отдельно; шесть их локальных unit-тестов прошли. Эти новые проверки не заменяют сквозной тест движков.

Новые статусы и поля отличаются от `app/contracts.py`; потребуется явный адаптер, а не предположение о совместимости.

## 5. Достоверность фактов и подтверждение человеком

Меры в `app/ai/validation.py` и сервисе:

- Непустое AI-поле требует источников, существующих в предоставленных пользователем данных.
- Цитата должна быть полным источником или полным предложением по консервативному разделителю; произвольный фрагмент, обрезающий отрицание, отклоняется.
- Значение поля должно совпадать с соединением цитат после нормализации пробелов; свободный пересказ не допускается.
- Ответ на вопрос назначен конкретному полю; его нельзя автоматически использовать как ответ на другой вопрос.
- AI не заполняет контакт. Старые ручные источники не включаются в новый контекст без контроля актуальности.
- Ручная правка становится новым пользовательским источником. Пользователь может изменить и подтвердить поле; код не доказывает истинность его утверждения.
- При смене значения или снятии подтверждения опубликованная карточка возвращается в черновик. Публикация требует хотя бы одного непустого поля и подтверждения всех непустых полей.
- Во время активного AI-прогона правки карточки заблокированы, устаревшие ответы/ревизии отклоняются.

**Граница гарантии:** цитата подтверждает происхождение, но не объективную истинность, релевантность или отсутствие смысловой манипуляции между предложениями. Дополнительная проверка судьи вероятностная. Полнота и достоверность разделены: пустое поле не оправдывает выдуманный факт. Для качества карточки это сознательно строгий компромисс: дословные формулировки могут быть менее гладкими.

## 6. Детерминированный рейтинг и каталог

`app/scoring.py` начисляет максимум 100: context 10, need 10, data 20, expected_result 15, success_criteria 15, constraints 10, users 10, contact 5, interaction_format 5. Название даёт 0.

Только `confirmed` может получить баллы. Для обычного текста требуется минимум 20 символов и содержательные символы. Контакт проверяется регулярными выражениями. Данные должны содержать источник/формат/пример; отсутствие, недоступность или будущее получение обнуляют этот критерий. Неоднозначная смешанная доступность тоже консервативно даёт 0 до уточнения. Для ограничений нужны маркеры срока, технологии, доступа или границы. Критерий успеха без измеримого маркера получает 7.5 из 15.

Это **эвристики**, не автоматическая экспертиза полезности: формальный числовой маркер может не быть хорошей метрикой; длинный текст может оставаться слабым. Интерфейс показывает начисления, причины и возможности роста, отсортированные по потенциальной прибавке.

Пороговые сравнения: менее 40 — draft, от 40 — working, от 70 — ready, от 90 — priority. Так как возможны половинные баллы, интервалы нужно понимать как `[0,40)`, `[40,70)`, `[70,90)`, `[90,100]`.

В каталоге только опубликованные карточки, включая нулевой балл. Сортировка по рейтингу и новизне публикации; фильтры — отрасль и уровень. Редактирование с последующей перепубликацией обязательно, поэтому временное исчезновение изменённой карточки связано с подтверждением, а не низким рейтингом.

## 7. API и пользовательский интерфейс

Ответы API — непосредственные объекты/массивы. Pydantic ограничивает структуру и длины. Отсутствующий объект — 404, неверный переход — 409, ошибки входной схемы — 422.

| Группа | Методы |
|---|---|
| Задачи | `POST/GET /api/tasks`, `GET /api/tasks/{id}` |
| AI | `POST .../{id}/analyze`, `GET .../{id}/run`, `POST .../{id}/answers` |
| Карточка | `PUT .../{id}/card`, `POST .../{id}/publish` |
| Каталог и команды | `GET /api/catalog`, `/api/teams`, `/api/leaderboard` |
| Отклики | `POST/GET /api/tasks/{id}/proposals` |
| Решение и прогресс | `POST /api/proposals/{id}/decision`, `.../{id}/stage` |
| Диагностика | `GET /api/health`, `/api/ai/contract` |

React реализует рабочую область бизнеса, открытый каталог, карточку, форму отклика, сравнение/решения по откликам и лидерборд. Есть ручной переключатель роли, выбор заглушки/AI, вопросы с баллами, источники полей, подтверждения и шкала рейтинга. Карта рассуждения представлена узлами и ссылками между ними; это не полноценный редактор графа. Во время работы сервер опрашивается примерно раз в секунду; предусмотрена защита от устаревшего ответа при смене задачи и предупреждение о несохранённых правках.

Число откликов не ограничено, включая несколько от одной команды. Можно принять несколько предложений. Этап подтверждается только для принятого отклика; после подтверждения отклонение этого отклика запрещено.

## 8. Хранилище и синтетические данные

SQLite хранит таблицы tasks/teams/proposals с первичным ключом и JSON тела модели. Параметры SQL передаются отдельно; названия таблиц определены внутри кода. `RLock` сериализует обращения одного экземпляра. Начисление +10 и отметка этапа выполняются в одной `BEGIN IMMEDIATE` транзакции: повторные запросы не увеличивают баллы вновь, проверено также на разных соединениях.

Начальный набор `seed/data.json`: 5 черновиков, 5 опубликованных карточек, 5 команд, 5 откликов. Баллы карточек: 20, 50, 75, 100, 100. Seed проверяет модели и ссылки откликов, повторная загрузка использует INSERT OR IGNORE и не стирает пользовательские изменения.

`SANA_DB` имеет приоритет над совместимым `DB_PATH`. Каталоги для БД создаются автоматически. Соединение закрывается при остановке приложения, включая ошибку завершения AI-сервиса; ошибка загрузки seed также закрывает соединение.

## 9. Безопасность и эксплуатационные ограничения

Это локальный MVP без аутентификации и разграничения владельцев. Переключатель «бизнес/студент» — UI, а не защита API. При открытии сервера посторонним они смогут читать и менять данные; для публичной эксплуатации потребуются настоящая авторизация и проверка прав на каждый объект. В рамках кейса сложная ролевая система не обязательна.

Ключи находятся на сервере в переменных окружения. `.env`, локальные БД, трассы и артефакты исключены из Git. Трассировщик маскирует значения переменных API_KEY/TOKEN, но это не универсальная очистка любых секретов или персональных данных из пользовательского текста. Трассы содержат реальные тексты запросов/ответов и требуют осмотрительного обращения.

Контактное поле исключается из контекста моделей; в свободном тексте обнаруживаются некоторые e-mail/телефоны/известный контакт. Это не всеобъемлющий детектор чувствительных признаков, имён, национальности и других категорий. Не использовать реальные персональные данные в демо. Профили команд предусматривают интересы, навыки и технологии.

Встроенная защита внешнего API включает бюджет вызовов, timeout, проверку JSON/цитат и явную ошибку. Автоматической подмены неуспешного AI вымышленным успехом нет. Для продакшена отдельно не проверялись нагрузка, резервное копирование, многопроцессное исполнение AI, rate limiting и устойчивость к злоупотреблению публичным API.

Браузерный сценарий по журналу интегратора: слабый черновик → 4 и затем 3 вопроса → источники → подтверждение → 100 → публикация → отклик Data Qanat → ручной выбор → +10. Три последовательных финальных репетиции не завершены.

```powershell
python -m venv .venv
```

В отдельном терминале:

```powershell
python -m pytest -q -p no:cacheprovider --basetemp=artifacts/external-audit-tests-new
```

Суффиксы `new` заменить новым уникальным именем, чтобы не перезаписывать предыдущую проверку. Затем пройти `DEMO.md` вручную.
