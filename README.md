# hack-5273bcd8-papanda

## AI Sana Challenge Hub (конкурсная реализация)

Веб-приложение превращает описание потребности бизнеса в проверяемую карточку,
показывает рейтинг готовности, публикует задачу и позволяет командам откликаться.
Бизнес сам выбирает команды и подтверждает выполненный этап.

**Документы:** [ТЗ](TASK.md), [демо до пяти минут](DEMO.md),
[инструкция запуска и архитектура](docs/MVP.md), [общие интерфейсы](CONTRACT.md),
[решения](DECISIONS.md), [проверки и ограничения](docs/VERIFICATION.md).

### Быстрый запуск

Нужны Python **3.11+**, Node.js **20.19+** и npm. Из корня репозитория:

```sh
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux/macOS вместо предыдущей строки: source .venv/bin/activate
pip install -e ".[test]"
sana
```

`sana` при первом запуске выполняет `npm ci` и `npm run build`, затем запускает один
сервер: **http://127.0.0.1:8000**. Первый запуск требует сети для загрузки зависимостей.
После установки и сборки режим `AI_MODE=stub` работает без сети и личных аккаунтов.
SQLite создаётся автоматически, начальный набор — 5 черновиков, 5 опубликованных
карточек разной готовности, 5 команд и 5 откликов. Все данные синтетические.

Если порт занят, задайте `PORT=8765` в `.env` (или `$env:PORT='8765'` в PowerShell).
Не останавливайте чужой процесс. Путь БД настраивается `SANA_DB`.
Для чистой проверки укажите **новый** путь БД: `SANA_DB=data/review.sqlite3`.

### AI и отсутствие выдуманных фактов

По умолчанию включена явно обозначенная **локальная заглушка**: она показывает
полный интерфейс и детерминированные вопросы, но не имитирует живой AI-анализ.
Для реальных моделей скопируйте `.env.example` в `.env`, заполните серверный
`OPENAI_API_KEY` и два разных имени `AI_ACTOR_MODEL` / `AI_JUDGE_MODEL`, затем выберите
«Текущий AI» в интерфейсе. `.env` исключён из Git. Проверка подключения:

```sh
python scripts/check_api.py
python scripts/check_api.py --model gpt-4.1-mini
```

Последняя команда делает короткий платный запрос. Разные провайдеры настраиваются
через `AI_ACTOR_API_KEY/BASE_URL` и `AI_JUDGE_API_KEY/BASE_URL`.
Купон NVIDIA Brev оплачивает инфраструктуру и не является ключом NVIDIA NIM API.

AI строит мир из цитируемых утверждений, сопоставляет потребность бизнеса с
возможностью студента начать работу, предлагает пробелы/противоречия, получает
независимую модельную проверку и задаёт вопросы. Ответы человека меняют мир.
Карточка проходит программную проверку источников и отдельную оценку модели-судьи.
Непредоставленные сведения остаются пустыми. Поля редактируются и подтверждаются
человеком; публикация и выбор команд не поручаются моделям.

**Граница гарантий:** точная цитата подтверждает происхождение текста, но не его
истинность и не безошибочность интерпретации. Извлечение только полных источников
или предложений защищает от обрезки отрицания; смысл дополнительно проверяют судья
и бизнес. Все новые AI-предложения требуют подтверждения.
Контакт вводится вручную и исключается из контекста моделей. Не вводите в описание
персональные или чувствительные сведения; профили команд содержат только навыки и интересы.

### Рейтинг и правила каталога

Рейтинг — детерминированная сумма за **подтверждённые** поля:

| Поле | Максимум |
|---|---:|
| Контекст / потребность | 10 + 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения / пользователи | 10 + 10 |
| Контакт / формат консультаций | 5 + 5 |

Название не даёт баллов. Текстовые поля требуют минимум 20 символов; контакт —
e-mail, телефон или @handle. Данные требуют указанного доступного источника/формата;
отсутствующие, обещанные или недоступные материалы не приносят баллы. Смешанная
доступность трактуется консервативно до уточнения. Ограничения должны содержать
срок, технологию, доступ или иную границу. Неизмеримый критерий успеха получает
7.5 вместо 15 баллов. Каждое правило объясняется в интерфейсе.

Уровни: 0–39 — требует уточнения, 40–69 — рабочая, 70–89 — готовая, 90–100 —
приоритетная. Каталог сортируется по баллу, затем по новизне публикации.
**Низкий балл не скрывает опубликованную задачу и не запрещает отклик.**
Публикация требует подтверждения всех непустых полей. Правки снимают публикацию
до нового ручного подтверждения. Полноценной регистрации в MVP нет; переключатель
«Бизнес/Студент» демонстрационный и не является системой авторизации.

Можно отправить несколько предложений и выбрать несколько команд или ни одной.
За один подтверждённый этап выбранная команда получает +10; повторный запрос не
начисляет баллы снова. Автоматического назначения команды нет.

### Проверки

```sh
python -m pytest -q
python scripts/record_demo.py --mode stub --output artifacts/demo-stub
```

Тесты проверяют источники, запрет новых фактов, подтверждения, рейтинг, публикацию
низкого балла, отклики, ручной выбор, постоянное хранение и однократное начисление.
Живой тест — только явно: `DIALECTIC_RUN_LIVE=1` и
`python scripts/record_demo.py --mode engine --output artifacts/demo-live`.
Он записывает реальные запросы/ответы приложения и метрики, использует синтетические
ответы бизнеса и расходует API-кредиты. Запись заглушки не считается живым прогоном.

Готовый код DialecticAI не переносился. Использована ранее разработанная методология;
конкурсная реализация `app/`, `engines/` и `web/` написана с нуля после объявления старта.

### Два новых взаимозаменяемых движка

В интерфейсе можно выбрать «Лёгкий движок» или «Тяжёлый движок». Оба получают один
`StartRequest` (черновик и веса полей), возвращают вопросы с `contradiction_id`,
`GraphView` и `CardDraft` с цитатами. Ответы проходят через отдельный канал ожидания.
Карточка попадает в обычный сценарий редактирования и ручного подтверждения; рейтинг,
публикация и выбор команды остаются в коде приложения. Для выбора движка через
конфигурацию установите `AI_MODE=engine` и `ENGINE=light` либо `ENGINE=heavy`.
Для клиентов новых движков укажите `ACTOR_PROVIDER`/`ACTOR_MODEL` и
`JUDGE_PROVIDER`/`JUDGE_MODEL`; имена моделей должны отличаться. Поддерживаются
OpenAI-совместимый endpoint и GigaChat. Одного купона NVIDIA Brev недостаточно для
вызовов NVIDIA NIM — нужен отдельный ключ API.

Лёгкий движок использует фиксированный конвейер анализа, узкой проверки судьёй,
вопросов и сборки карточки. Тяжёлый выбирает разрешённые ходы открытого графа,
проверяет каждый ход и фиксирует наблюдения от вопросов и проверки карточки.
Противоположность (потребность студенческой команды) в обоих движках определена
доменом; модель развивает её, но не выбирает заново. Контракт и методы находятся в
`engines/common/contracts.py` и `engines/__init__.py`. Отдельный HTTP-сервис:

```sh
uvicorn engines.service:app --host 127.0.0.1 --port 8001
```

Его маршруты: `POST /engine/runs`, `GET /engine/runs/{id}`,
`POST /engine/runs/{id}/answers`, `DELETE /engine/runs/{id}`,
`GET /engine/runs/{id}/trace`, `/engine/contract`, `/engine/health`.
Промпты и схемы доступны в `/engine/contract`. Тесты двух движков работают с
`ScriptedLLM` без сетевых вызовов. Живую устойчивость и заявленные задержки
следует проверять отдельно; локальные тесты их не доказывают.

Ниже сохранено исходное описание демонстрационного агента организатора.

Небольшой демонстрационный терминальный агент на Python. Он отвечает на
несколько команд и умеет сохранять задачи в локальный файл `tasks.txt`.

## Запуск

Требуется Python 3.10 или новее.

```powershell
python mini_agent.py
```

В чате напишите `помощь`. Доступные команды: `время`, `задача <текст>`,
`задачи` и `выход`.

`tasks.txt` создаётся во время работы и намеренно не хранится в Git.
